## What varies on one broker

The earlier one-broker nonregression interval remains inconclusive. In the larger common-client campaigns and most later groups, ACK time tracked whole-client system CPU more strongly than user CPU. Page faults covaried with ACK time in the serial-audit runs, but large timing spread remained after streaming audit reduced and stabilized faults. This motivated two fixed, identical-binary controls, both with the same frozen broker SHA256 `cb024e...` and source5 client SHA256 `bc0fa7...`, one broker, 2 GiB of 4 KiB indexed messages, ORDER5/ACK1/RF0, a fresh 64 GiB DRAM-emulated region per run, client node 0, broker node 1, and exact streamed delivery audit. Each control had two excluded qualifications and eight predeclared measurements. All 20 trials passed delivery, routing, identity, normal-exit, and owned-cleanup checks. They are diagnostics, not a baseline-versus-candidate comparison or CXL results.

In the first control, the eight identical-binary measurements spanned 1.325–2.167 seconds to ACK and 1.811–2.194 seconds to complete the audited delivery. The publisher send thread's sampled system CPU tracked ACK time (`r=0.956`); sampled runnable wait for all client threads was only 0.72–2.34 ms. Whole-client fault counts were comparatively steady. Identical binaries would have produced a misleading 0.799 candidate/baseline geometric ACK ratio if the alternating schedule labels had been mistaken for treatments; the audited E2E ratio was 1.007. The 250 ms observer cost 9.64–10.94 CPU seconds over each roughly minute-long lifecycle on an otherwise separate core, so these timings must not be compared as an absolute speedup against unobserved runs. Per-thread CPU covers varying interior windows (85–97% of audited E2E), and correlation does not establish the precise kernel cause. The [compact control evidence](evidence/2026-09-23-controls.json) preserves each measured trial; complete raw logs and manifests remain in the local results directory.

The second control enabled existing network-path counters **only in the client** and used a lighter named-process monitor. In all eight measurements, 1,041 counted `send()` calls transferred the same 2,181,171,328 bytes through the combined batch-header/payload path. `EAGAIN`, writable waits, and writable wait time were zero in every run. ACK completion took 1.315–2.210 seconds; summed `send()` wall time took 1.312–2.207 seconds and differed from ACK completion by only 2.5–3.4 ms per run. Publisher-pool waits rose with the send time (0.712–1.341 seconds), consistent with producer backpressure from the finite pool. Client system CPU also rose. The socket is created with `O_NONBLOCK` in `GetNonblockingSock`, so these runs did not enter the explicit epoll backpressure path. The existing counter times each `send()` call; it does not distinguish copying, TCP/loopback work, softirq execution, or time involuntarily spent inside the syscall. The profile itself adds per-call timing overhead, and its absolute throughput is not compared to the first control. Its fixed protocol, analysis, and raw manifests/logs remain under `results/refactor-next/2026-09-23/`; the linked compact evidence contains the measured counters.

These controls identify where the variable ACK time is observed: the client's combined header/payload `send()` path, with pool wait covarying with it. They do **not** identify a recent refactor as the cause, prove the broker is faster or slower, or settle the 5% nonregression gate. The counters prioritize profiling the sender/kernel path; they do not yet justify another subscriber or broker change or rule out downstream influence. The next causal experiment should hold these binaries and audit constant while isolating kernel/network behavior or CPU placement, with one preregistered intervention at a time and a matched no-intervention control. Any proposed code optimization then needs its own correctness gates and paired, audit-qualified ACK and E2E comparison. Physical CXL, remote clients, small/partial batches, and latency remain separate qualification work.
